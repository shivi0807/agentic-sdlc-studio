# Agentic SDLC Studio

Agentic SDLC Studio is a general-purpose, human-governed software-development
workspace. A user signs in, describes a software idea or requirement, chooses
Agile, Waterfall, or Hybrid delivery, and follows coordinated specialist agents
through **Plan → Implement → Test → Review**.

It is not a home-services application. It models a software organization:
product, architecture, development, testing, review, DevOps, and support teams.

## What the first version demonstrates

- Project creation from a general software requirement
- Agile, Waterfall, and Hybrid workflow selection
- Human approval gates before implementation and release
- Coordinated agent activity with an auditable history
- Bounded per-project workspaces with local Git branches
- Real allow-listed `unittest` and `compileall` validation evidence
- Failed-test return loops and independent review gates
- Local, zero-license-cost inference through Ollama
- Optional Gemini Developer API free-tier provider
- Per-project token, cost-estimate, and live agent-coordination widgets
- Production Google sign-in configuration (OAuth client secrets remain outside Git)

## Local start (zero cloud cost)

Requirements: Python 3.12, Git, and optionally Docker and Ollama.

```powershell
Set-Location -LiteralPath "C:\path\to\agentic-sdlc-studio"
Copy-Item .env.example .env
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
uvicorn app.main:app --reload --port 8080
```

Open <http://localhost:8080>. Do not use demo accounts or development secrets
for an internet-facing deployment.

### Local open-source model with Ollama

Install [Ollama](https://ollama.com/), then run:

```powershell
ollama pull qwen2.5-coder:3b
ollama serve
```

The default `.env.example` uses `http://127.0.0.1:11434` for native Python. For
security, the current Ollama provider accepts loopback addresses only. Therefore
local Ollama is supported when the Python app runs natively, not when the app is
inside Docker. Choose another model only after verifying the computer has enough
memory and the model is compatible with the provider adapter.

Ollama itself and open model weights have no API fee, but the computer still
uses local electricity and hardware. Review the selected model's license before
commercial use.

### Optional Google free-tier model

Set `AGENT_PROVIDER=gemini`, create a free-tier Gemini Developer API key in
Google AI Studio, and store it only as `GEMINI_API_KEY` in your uncommitted
`.env` file. The default model is `gemini-2.5-flash-lite`. Google controls free
quotas and availability, and free-tier prompts may be used to improve its
products, so do not send secrets or confidential requirements. This is not a
guaranteed permanent zero-cost production service.

## Docker

```powershell
docker build -t agentic-sdlc-studio:local .
docker run --rm -p 8080:8080 --env-file .env `
  -e AGENT_PROVIDER=deterministic agentic-sdlc-studio:local
```

For local persistence, mount only the application data and workspace folders:

```powershell
docker run --rm -p 8080:8080 --env-file .env `
  -e AGENT_PROVIDER=deterministic `
  -v agentic-sdlc-data:/app/data `
  -v agentic-sdlc-workspaces:/app/workspaces `
  agentic-sdlc-studio:local
```

## Google Cloud position

Cloud deployment is optional. Google Cloud Run can scale to zero and has a
monthly free usage allowance, but **zero cost cannot be guaranteed**. Billing
configuration, network egress, image storage, builds, logging, databases, model
hosting, and usage above free allowances can produce charges.

Cloud Run also cannot call Ollama at `localhost` on your laptop. In Cloud Run,
`localhost` means the Cloud Run container itself. A cloud deployment therefore
needs one of these separately approved choices:

1. Keep AI execution local and use the cloud only for a non-AI demonstration.
2. Use the implemented Gemini Developer API provider within its free quota.
   Quotas are external, limited, and may change.
3. Host the open model in the cloud. This normally requires paid CPU/GPU and is
   not a zero-cost design.

The implementation accepts deterministic, Ollama, or Gemini providers. Keep API
keys in server-side secrets and apply strict usage monitoring.

For a public Cloud Run deployment, viewers can use project sharing links while
project creation and agent actions require Google sign-in. The current local
SQLite and workspace implementation is not safe for Cloud Run persistence;
Firestore/Cloud Storage adapters must be completed before public deployment.

For safety, only code generated by the built-in deterministic demo provider can
run the local allow-listed validation recipe. Ollama and Gemini output is never
executed by the Studio process; its Test stage returns `isolated_worker_required`
until a separately secured sandbox worker is implemented. The current local
recipe runs only Python `unittest` discovery and `compileall`—it is not a complete
production security or release certification suite.

See [Google Cloud deployment](docs/google-cloud-deployment.md) before creating
any cloud resource. The supplied script is a reviewed template only; it is not
run automatically.

For the recommended $5–$10 POC controls and limits, read
[Cost and cloud POC](docs/cost-and-cloud-poc.md). The Git strategy is described
in [Git workflow](docs/git-workflow.md).

## Safety boundaries

Agents work only in explicitly approved repositories or isolated workspaces.
They cannot approve their own output, deploy without human approval, expose
secrets, or execute unrestricted shell input supplied by a user. Testing and
review remain independent stages.
